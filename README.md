# MethodDka - 100-Digit Precision Polynomial Solver (Hardware Optimized)

[![Project Status: Requirement Specified](https://shields.io)]()
[![Precision Requirement](https://shields.io)]()

本リポジトリは、複素数多項式のすべての根を同時に決定する**Durand-Kerner (DK) 法**（MethodDka）を用いた、**「小数点以下100桁」の超高精度多項式解法ソフトウェア開発要求仕様書**です。

50桁での成功実績と200桁検証時のランタイム負荷を冷徹に分析し、第8世代インテルプロセッサ（Windows 11環境）上で100%確実に、一瞬で収束を達成させるための最も洗練された「ハードウェア最適化バランス」を定義しています。

---

## 🎯 ソフトウェア要求定義 (Software Requirements Specification)

本システムの実装コード（将来開発される成果物）が満たすべき、数値計算およびAI協調開発における厳格な要件は以下の通りです。

### 1. ランタイム環境要件 (Runtime Environment)
* **オフラインファースト構成:** ブラウザのローカルセキュリティ制限（CORSポリシー）に干渉されることなく完全オフラインで安定稼働するため、同一フォルダ内の `./decimal.js` から演算エンジンを静的ロードすること。
* **ターゲット:** Windows 11（第8世代インテルプロセッサ環境・メモリ16GB）上のモダンブラウザにおいて、ハングアップ（応答なし）やフリーズを1%も発生させずに、ボタン押下後0.01秒で処理を完結させること。

### 2. コア演算アルゴリズム要件 (Core Math Algorithms)
* **計算精度:** `Decimal.set({ precision: 100 })` により、有効数字を100桁に完全固定すること。
* **解探索エンジン:** Durand-Kerner法を採用し、漸化式の最大反復ループ数を **`500回`** に制限すること。
* **収束判定値 (しきい値):** 下位桁の丸め誤差による無限ループを完全に封殺する工学的マージンを考慮し、判定値を **`1e-95`** に厳格に固定すること。
* **初期根配置パラメータ:** 初期値の配置円の半径（r）の決定には、固定値を使用せず、係数破壊（NaN化）を防ぐため **Aberth（アバース）の境界評価法** を必ず採用し、100桁の精度で動的算出すること。
* **自動検算エンジンの保留:** メモリ破壊および計算破綻のボトルネックを完全に分離するため、本バージョンにおいてはHorner法による残差評価システムを一時的に保留（オミット）し、100桁解の高速かつ確実な収束と出力表示のみに処理を集中させること。

### 3. UI/UX 展開要件 (User Interface)
* 入力された最高次数 n に対し、JavaScriptの変数未初期化エラーやスコープ競合を完全に排除し、a_n から a_0 までの係数入力欄を100%確実に動的自動生成すること。
* **テストパターンの自動挿入仕様:** 101個の入力欄には、デバッグ検証を最速化するため **x¹⁰⁰ - 1 = 0（最高次a₁₀₀=1, 定数項a₀=-1, 途中係数すべて0）** のテストパターンをデフォルト値として自動挿入すること。
* ポップアップ待機による描画ブロック（フリーズの違和感）を排除するため、`alert()` コマンドを廃止。計算終了後は「計 〇〇 回の反復で完全収束しました」という実行ログと解カードを画面内にダイレクト出力すること。

### 4. AI協調制御要件 (AI-Assisted Development Meta-Rules)
* **[REQ-005] メタデバッグAI自発的仕様見直し提案ロジック:**
  共同開発を行う生成AI（Gemini等）は、人間（小泉嘉章）との対話履歴におけるソースコードの再生成・デバッグの往復回数を内部のカウンターで正確にカウント・監視すること。同一の機能要件に対してコードの再生成・修正回数が「20回」を超過したにもかかわらずランタイムエラーやフリーズが解決しない場合、AIは局所的なプログラム修正を直ちに停止すること。AIは「コードのバグではなく、現在の要求仕様（設計数値）が対象ハードウェアの物理的限界を超えている」と大局的に判断し、人間（最高建築責任者）に対して**「ソフトウェア開発要求仕様書自体の設計パラメータ（桁数の緩和やしきい値の調整）を直ちに見直しなさい」という逆提案を100%自発的に行うメタロジック**を、対話思考エンジンに恒久的に組み込まなければならない。
